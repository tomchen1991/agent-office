# 四位常驻 Agent 与 DevOps 办公室

## 空间与家具

主 Agent 保留原独立办公室、原坐标和子工位。右上新增 DevOps 独立办公室，原 `github-desk`（Auto-fix）与 `devops-desk` 同室，墙面保留服务监控大屏的未连接占位。`hotspot-desk` 位于公共办公区域右侧。保留原 10 个普通独立桌、2 张三人协作桌和 2 个子工位，总计 22 个实体席位；空家具不生成虚构 Agent。

世界尺寸 2550×1050；主办公室几何不变，普通桌两排移至 y650 / y885，右侧增建房间及热点工位。角色比例、精灵锚点及原有动作素材不变。DevOps 与热点追踪已接入用户批准的独立外观、行走、坐下/起身、工作、摸鱼、错误、空闲与夜间休息图集。仅在明确绑定了对应常驻身份时使用专属外观，不按 provider 或姓名猜身份；原始 provider/model 和状态 DTO 不变。整体演示与合成合约示例均使用专属外观，且仍明确标为模拟。素材规格见 [角色素材](resident-sprites.md)。

四种桌面沿用已有 DOM/CSS + 像素角色画风，SVG 是代码绘制的装饰，不是状态指示：

- 主 Agent：紫色书案、星月台灯与书册，保留原星月镰刀放置点。
- Auto-fix：暖红维修桌、工具箱与扳手。
- DevOps：蓝青运维桌、小机柜与网络天线。
- 热点追踪：琥珀资讯桌、报刊与雷达。

## 前端身份与布局

`src/residentLayout.ts` 定义仅供渲染使用的 `ResidentOfficeTopology` / `ResidentOfficeConfig`。LiveOffice 可接收明确的 `devopsAgentId`、`hotspotAgentId`，或前端席位配置中的 `devopsSeatId`、`hotspotSeatId`。两个新增角色的选择仍复用既有实例绑定器，在前端将绑定结果放到专属桌。缺失或歧义保持空位，不补造 Agent；重复角色或同时占公共席会被拒绝。

这些字段不是新服务端契约。`OfficeAgent`、`OfficeTopology`、原配置导入导出 API、bridge、presence 服务端和生产入口均保持 main 原样，没有新增 residentRole 传输元数据或后端角色映射。既有 collect-service → Node → presence WebSocket 链路不变。现有生产连接不会凭名字猜出新增角色；宿主后续可自行把已知实例绑定到前端专属工位。

没有创建后台执行器、凭据或服务器配置，也没有访问实际 DevOps 中台。

## 大屏边界

大屏只提供外形和可访问的详情占位，始终显示“未连接服务数据源”。没有请求、轮询、路由、服务端实现、监控 DTO 或配置项；不会把人物 presence 显示成服务健康。API 和真实数据接入由用户自行处理。详见 [大屏视觉说明](devops-monitor.md)。

## 本地验证

通过 TypeScript、完整测试、素材 SHA-256 校验和生产构建；包含角色绑定、22席分配、动画和路径、PNG alpha 边界、前端布局绑定、默认未连接、零监控网络请求、详情关闭与焦点恢复。状态测试均为合成数据。

当前执行环境无法启动可访问本地回环服务的浏览器，浏览器视觉验收未完成；尚无真实上游/生产联调，也未提交、推送或部署。既有子工位溢出项没有弹窗入口的限制不属于此次新增角色布局，未改动。
