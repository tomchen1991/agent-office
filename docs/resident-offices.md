# 四位常驻 Agent 与 DevOps 办公室

## 空间与家具

左侧上下排列两间等宽办公室：上方为主 Agent，下方为 DevOps / Auto-fix 共用办公室，墙面保留服务监控大屏的未连接占位。`hotspot-desk` 位于公共办公区域右上方。撤掉主办公室的两个固定子工位，PI 按需使用公共协作桌，满后使用公共独立桌；显式团队席位优先保留。保留原 10 个普通独立桌、2 张三人协作桌，总计 20 个实体席位；空家具不生成虚构 Agent。

世界尺寸 2250×1050；主 Agent 大工位坐标不变，缩短上方办公室并在下方安排运维办公室，普通桌两排紧凑排列于 y570 / y795，热点工位位于原 Auto-fix 的右上位置（1840, 300）。角色比例、精灵锚点及原有动作素材不变。DevOps 与热点追踪已接入用户批准的独立外观、行走、坐下/起身、工作、摸鱼、错误、空闲与夜间休息图集。仅在明确绑定了对应常驻身份时使用专属外观，不按 provider 或姓名猜身份；原始 provider/model 和状态 DTO 不变。整体演示与合成合约示例均使用专属外观，且仍明确标为模拟。素材规格见 [角色素材](resident-sprites.md)。

四种桌面沿用已有 DOM/CSS + 像素角色画风，SVG 是代码绘制的装饰，不是状态指示：

- 主 Agent：紫色书案、星月台灯与书册，保留原星月镰刀放置点。
- Auto-fix：暖红维修桌、工具箱与扳手。
- DevOps：蓝青运维桌、小机柜与网络天线。
- 热点追踪：琥珀资讯桌、报刊与雷达。

## 门窗与分区

两间左侧房间使用统一的实墙细边与真正留空的右侧门洞，移除旧斜门框、虚线门边和整条玻璃墙装饰。`OFFICE_ROOMS` 同时定义房间尺寸与门洞，主办公室门洞 y=420–520、运维门洞 y=700–800，进出路线分别穿过 y=470 / 750 中心，不再独立硬编码门的位置。

主办公室上沿两扇、公共区域上沿三扇双格窗，窗框、玻璃、窗台使用同一尺度。窗户直接位于可见世界 y=135–199，不再跟随默认展示会裁掉的顶部背景墙消失。运维上墙留给大屏，不额外挤窗，不添加房间标题或工具栏。墙窗是背景层，仍需浏览器检查角色经过门洞时的遮挡观感。

## 前端身份与布局

`src/residentLayout.ts` 定义仅供渲染使用的 `ResidentOfficeTopology` / `ResidentOfficeConfig`。LiveOffice 可接收明确的 `devopsAgentId`、`hotspotAgentId`，或前端席位配置中的 `devopsSeatId`、`hotspotSeatId`。两个新增角色的选择仍复用既有实例绑定器，在前端将绑定结果放到专属桌。四类常驻身份按单实例设计，本轮不扩展重复实例处理；缺失绑定保持空位，不补造 Agent。

这些字段不是新服务端契约。`OfficeAgent`、`OfficeTopology`、原配置导入导出 API、bridge、presence 服务端和生产入口均保持 main 原样，没有新增 residentRole 传输元数据或后端角色映射。既有 collect-service → Node → presence WebSocket 链路不变。现有生产连接不会凭名字猜出新增角色；宿主后续可自行把已知实例绑定到前端专属工位。

没有创建后台执行器、凭据或服务器配置，也没有访问实际 DevOps 中台。

## 大屏边界

大屏只提供外形和可访问的详情占位，始终显示“未连接服务数据源”。没有请求、轮询、路由、服务端实现、监控 DTO 或配置项；不会把人物 presence 显示成服务健康。API 和真实数据接入由用户自行处理。详见 [大屏视觉说明](devops-monitor.md)。

## 本地验证

本轮按 20 席与上下两间办公室更新几何断言；状态测试均为合成数据，不代表真实上游联调。自动化不能替代实际浏览器的透明边界、遮挡和通道验收；本次不提交、推送或部署。

子 Agent 与团队超量成员现在复用无工位显示层，可靠空闲时游荡、工作时原地使用平板（素材未到时站姿兜底），均可点击查看详情，见 [超量角色与素材契约](overflow-agents.md)。默认展示页不增加工具栏或成员名单。

全屏展示保持统一比例，按可见 2250×930 地面适配视口，只裁掉上方 120 单位背景墙；宽屏允许留白，窄屏使用等比滚动画布，不再独立拉伸世界高度。
