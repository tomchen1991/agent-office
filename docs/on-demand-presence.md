# 按需服务 presence

`src/presenceConfig.ts` 明确配置 `get-news-worker` 为热点工位的按需服务。它是配置的逻辑身份，不是常驻进程，也不表示已验证健康；不按名称或模型猜测身份。

Worker 协议：任务开始上报 `working`，长任务每 15 秒更新，结束发 `stopping`，之后不再发送。

展示规则：

- 首次尚无任务时显示「待命 · 按需唤醒」。
- `working` / `waiting` 跟随事件；当前配置执行更新超时为 60 秒，超过则显示未知，不能自动视作完成。
- `stopping` 对该来源表示任务完成，转换成待命，不触发起身退场。普通 Agent 的 stopping → offline 行为不变。
- 待命不要求心跳，不因采集端过期、清理实例而消失。
- 逻辑 ID 稳定，Worker invocation ID 或采集进程重启不会使角色重新进出。
- 并发实例有歧义时显示未知，不凭空选择已完成状态。
- 采集连接断开仍显示未知，不能把「按需待命」当作网络或健康检查成功。

每个浏览器订阅独立保留最后任务状态，并在重连时继续使用。页面刷新后以当前快照和配置重建；如果采集端已清理所有记录，则无法还原历史未完成任务，只能显示配置待命。若需要跨页面刷新保留未完成任务或自动识别服务故障，必须由服务端提供持久化任务/可用性协议，不能由前端推测。

此改动只涉及展示端，不要求 Worker 新增待命心跳，不修改采集接口，也未部署生产。
