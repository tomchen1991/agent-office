# 已确认的产品方向

## 目标

采集端已存在，本项目负责消费端可视化：将各个 Agent 呈现为虚拟办公室中的可爱小人，让人直观看到它们在做什么。优先把布局和人物风格做对，再逐步推进事件模型与接入。

## 角色

最终四类身份，不是四种不同画风：

1. 自研 Agent：紫发双马尾、软萌洛丽塔裙装、小巧但华丽的星月紫晶镰刀。选择 A 强轮廓方向，当前 V2 外形和待机样例已认可。
2. DeepSeek：参考此前批准的 I 方案，蓝长发、鲸鳍饰、蓝眼、深蓝裙配白围裙、鲸尾。
3. ChatGPT / OpenAI：参考此前 V1，白长发、薄荷绿双角与龙尾、绿眼、绿色外套配白裙。
4. Grok：参考此前 V2，金色双马尾、紫眼、黑白哥特裙、酒红蝴蝶结、小黑翅膀。

四种角色均已有统一风格的动作图集，已接入场景；素材仍为高分辨率像素风原型。

## 空间关系

- 固定主办公室与公共区域同时存在，不再切换互斥布局。
- 主办公室：自研 Agent 的 1 个大工位，以及 1 张三人协作桌；协作桌给其子 Agent，最多展开 3 席，超出显示 `+N`。
- 公共区域：3 张协作桌，每张 3 席；另外 10 个完整独立工位。共 19 个公共席位。
- 总共 23 个实体席位。空席保留家具，不凭空创建角色、状态或请求；超出容量的已配置实例保留详情与明确提示。
- 自研 Agent 的办公室体现其长期身份地位，不是任何任务 leader 都进入单间。主从关系仍是显式数据，不改变固定家具布局。
- 每个公共成员可显式分配到具体物理席位；协作由同一张真实桌面表达，不依赖连线。

## 信息展示

展示状态和最近一次用户提出的请求摘要，点击后可展开摘要与时间。不要将用户请求摘要偷换成模型输出摘要。已核验消费端状态契约：状态接口不提供用户请求摘要、模型身份或团队关系。当前 Node 适配器只做状态轮询，缺失信息明确标记未知；真实部署联调与后续用户消息来源尚未接入。

## 动作

先验证站姿待机，再逐步探索从门口走到工位、入座、进入工作状态的连贯过渡，避免突然闪现。键盘工作可用，但不是每个状态必须打字。后续用户明确要求四角色全流程；现增加独立动作演示和各自实际姿态帧。其时间轴为模拟剧情，不推断采集端 idle 等于摸鱼或 unknown 等于 error。

## 技术与节奏

- React + TypeScript，Node.js / Electron 侧也使用 TypeScript。
- 接入现有 Electron 项目，具体目标路径与接口尚未指定。
- PixiJS 只是候选方案，当前不引入。
- 一步步验证，不因骨架存在就将全部功能视为实现。
