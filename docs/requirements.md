# 已确认的产品方向

## 目标

采集端已存在，本项目负责消费端可视化：将各个 Agent 呈现为虚拟办公室中的可爱小人，让人直观看到它们在做什么。优先把布局和人物风格做对，再逐步推进事件模型与接入。

## 角色

最终四类身份，不是四种不同画风：

1. 自研 Agent：紫发双马尾、软萌洛丽塔裙装、小巧但华丽的星月紫晶镰刀。选择 A 强轮廓方向，当前 V2 外形和待机样例已认可。
2. DeepSeek：参考此前批准的 I 方案，蓝长发、鲸鳍饰、蓝眼、深蓝裙配白围裙、鲸尾。
3. ChatGPT / OpenAI：参考此前 V1，白长发、薄荷绿双角与龙尾、绿眼、绿色外套配白裙。
4. Grok：参考此前 V2，金色双马尾、紫眼、黑白哥特裙、酒红蝴蝶结、小黑翅膀。

四种角色均已有统一风格的动作图集，已接入场景；素材仍为高分辨率像素风原型。

## 空间关系

- 固定主办公室与公共区域同时存在，不再切换互斥布局。
- 主办公室：自研 Agent 的 1 个大工位，以及 2 张独立办公桌；独立桌给其子 Agent，最多展开 2 席，超出显示 `+N`。
- 公共区域：2 张协作桌，每张 3 席；另外 10 个完整独立工位，共 16 个普通团队席位；原第三张协作桌改为 1 张 GitHub Agent 专属大桌。
- 总共 20 个实体席位。空席保留家具，不凭空创建角色、状态或请求；超出容量的已配置实例保留详情与明确提示。
- 自研 Agent 的办公室体现其长期身份地位，不是任何任务 leader 都进入单间。主从关系仍是显式数据，不改变固定家具布局。
- 每个公共成员可显式分配到具体物理席位；协作由同一张真实桌面表达，不依赖连线。

## 信息展示

展示状态和最近一次用户提出的请求摘要，点击后可展开摘要与时间。不要将用户请求摘要偷换成模型输出摘要。已核验消费端状态契约：状态接口不提供用户请求摘要、模型身份或团队关系。当前 Node 适配器只做状态轮询，缺失信息明确标记未知；真实部署联调与后续用户消息来源尚未接入。

## 动作

先验证站姿待机，再逐步探索从门口走到工位、入座、进入工作状态的连贯过渡，避免突然闪现。键盘工作可用，但不是每个状态必须打字。后续用户明确要求四角色全流程；现增加独立动作演示和各自实际姿态帧。其时间轴为模拟剧情，不推断采集端 idle 等于摸鱼或 unknown 等于 error。

### 空闲行为：留在工位（最新决定）

- Auto-fix 取消离座遛弯，在可靠空闲时留在工位循环打游戏，不自动进入起身/外出阶段。
- 自研主 Agent 保留拿取、玩耍、归还镰刀及必要短距离移动；现有图集没有独立打游戏动作，不将镰刀帧当成坐姿游戏帧。
- 有工作立即切回工作动画；不把未知或失鲜当作空闲。夜间休息及减少动态偏好继续保留。
- 普通未配置角色不凭空补造游戏素材，仍使用已有工位表现。动作演示页保留原演示，不影响实际接入。
- 下方随机路线方案已被此决定取代，不列入当前待办。

### 历史方案：空闲随机散步（已取消）

当前优先调试真实 presence 接入；用户要求先固化以下动画方向，不在接入调试期间改动散步实现。

- 仅连接正常、状态新鲜且明确 idle 时允许散步，先随机等待，不是每次空闲立即起身。
- 每轮重新选择可行走区域中的随机路线，正常未被打断时至少持续 60 秒；建议范围 60–120 秒。
- 绕开墙、桌椅等障碍，途中可短暂停留与转向；速度平滑，避免机械折返、穿模与瞬移。
- 收到 working 立即取消剩余散步，沿最短可行路线返回自己的工位，可适当加快回程；工作优先，不受一分钟最短时长限制。
- “立刻返回”指页面收到状态后立即开始返回，不是瞬移；当前 HTTP 轮询仍有检测延迟（约 5 秒轮询间隔及请求耗时）。
- 断连、状态失鲜或不再可靠空闲时中断散步表现，不继续把未知状态演成摸鱼。
- 仅为页面视觉行为，不更改 Agent 执行状态，不需要修改采集契约。
- 后续实现需验证：重复散步路线变化、未中断时长不少于 60 秒、障碍绕行、工作打断、失鲜中断与减少动态偏好。

## 技术与节奏

- React + TypeScript，Node.js / Electron 侧也使用 TypeScript。
- 接入现有 Electron 项目，具体目标路径与接口尚未指定。
- PixiJS 只是候选方案，当前不引入。
- 一步步验证，不因骨架存在就将全部功能视为实现。


## 四位常驻角色与运维房间（2026-11-10）

新增 DevOps、热点追踪两种固有身份，主 Agent 位置保留，Auto-fix 与 DevOps 同处新增独立办公室，热点追踪留在公共区。四种角色有独立桌面配色和装饰；真实角色身份必须由配置明确绑定，空席不生成虚构角色。服务大屏仅制作视觉，保持“未连接服务数据源”，API 与真实数据接入由用户自行处理；不改现有 presence 协议和连接。布局与验证边界见 `resident-offices.md`、`devops-monitor.md`。
